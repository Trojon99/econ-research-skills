# Validate the data behind a figure

Use the checks that apply when changing how a figure is produced: partitioning an extract, assigning records to places, adding predictions, or moving a chart into a browser. Start with the unit represented by **one mark**. For a district-year rate, for example, keep the district and year, numerator, denominator, unweighted count, missing-status rule and any interval endpoints in the figure source. A matching overall mean is not enough: two districts can exchange records without moving the overall result.

## Keep a partition boundary from changing the statistic

- **Choose a diagnostic slice by key, not by file position.** Include a unit whose history crosses two input files, a gap in dates, a missing outcome and groups with unequal denominators. Retain enough history on either side of the reporting window to compute lags or eligibility. Run a simple reference calculation on those same keys. Move the file boundary or change the partition count and compare the keyed results again. A lag must follow the intended calendar and unit, not the previous row in a file.
- **Combine amounts before computing a rate.** If two files contribute 2 of 4 and 9 of 36 eligible cases to the same cell, the result is 11 of 40 (27.5%), not the average of 50% and 25% (37.5%). For a weighted rate, combine weighted positive and eligible totals using the same eligibility rule. Do not add partition-level distinct-person counts when the same person can appear in both. Keep a cell with zero denominator distinct from an observed zero rate.
- **Check what will be read, then what was produced.** For a lazy query, inspect the scan, selected fields and filters in the plan. A filter on the *reported dates* belongs after a lag if earlier dates are needed to compute it. For partitioned processing, reduce to cell totals before collecting locally if those totals fit. Compare cell keys and integer counts exactly and weighted sums within a stated numerical tolerance before timing the new route. A fast plan or a passing slice does not replace full-output reconciliation. See the [Polars query-plan example](https://docs.pola.rs/user-guide/lazy/query-plan/) and [Dask guidance on reducing before collection](https://docs.dask.org/en/stable/dataframe-best-practices.html).

## Account for records before coloring a map

Record each layer's boundary vintage, geographic unit and coordinate reference system (CRS). Assign missing CRS metadata only from evidence about the original coordinates; transform coordinates when changing systems. For planar areas or distances, choose a projection appropriate to the quantity and region and record its units. Matching CRS labels alone do not establish accurate measurements. See [GeoPandas on projections](https://geopandas.org/en/stable/docs/user_guide/projections.html).

For a point-to-district join, keep an input row ID and count **distinct candidate districts per input**, retaining inputs with no candidate. Tabulate zero, one and multiple candidates with their input weight. A point on a shared edge can match neither district under strict containment or both under intersection; a nearest match can tie. Inspect those cases against the boundary vintage and assignment rule rather than retaining whichever row sorts first. If fractional allocation is justified, verify that each allocated input contributes its original total weight across destinations. Reconcile assigned plus unresolved weight to the input before calculating district rates. Display no eligible observations differently from a measured rate of zero. [Spatial join examples](https://geopandas.org/en/stable/gallery/spatial_joins.html) and [nearest-join semantics](https://geopandas.org/en/stable/docs/reference/api/geopandas.sjoin_nearest.html) document the match behavior, not a rule for assigning economic exposure.

## If the figure compares predictions with observations

Write down what is supposed to be new: a person not seen during fitting, a later period for a known unit, or both. Keep whole units apart for the first target; respect the forecast date, predictor availability and outcome horizon for the second. Check both restrictions if both are claimed. Fit imputers, scalers, feature selection and tuning **inside the training portion** of each split; a pipeline cannot repair a feature built from future outcomes before splitting. Save the held-out keys, cutoff or fold, observed outcome, prediction and a simple benchmark on the same rows. Label a fitted-versus-observed plot in-sample if that is all it is. Neither a good forecast nor the split itself identifies an intervention effect. See scikit-learn on [preprocessing and leakage](https://scikit-learn.org/stable/common_pitfalls.html) and [evaluation splits](https://scikit-learn.org/stable/modules/cross_validation.html).

## Inspect what the reader actually receives

- **Statistical plot:** Check uniqueness by facet, series and x-coordinate before drawing precomputed cells. A duplicate is a question about the data, not an invitation to average. Draw estimates and their approved endpoints directly; disable automatic estimation and error bars when using a statistical plotting function as a renderer. Compare an exported series, including missing periods, to the figure source. [Seaborn's line plot](https://seaborn.pydata.org/generated/seaborn.lineplot.html) illustrates why: repeated responses at an x-value can be aggregated and given a new interval. That is not a survey- or cluster-design interval merely because the input was weighted.
- **Dense static figure:** When a vector export is too large, try rasterizing just the dense point or mesh layer rather than dropping observations. Keep labels and axes as vectors; inspect the saved file at its intended print size for lost fine structure. The rendering choice changes resolution, not the underlying sample. See [Matplotlib's per-artist rasterization example](https://matplotlib.org/stable/gallery/misc/rasterization_demo.html).
- **Interactive figure:** Build the figure from a release-approved table, not from microdata with fields hidden in the tooltip. Inspect the serialized trace data, including hidden series, labels and auxiliary fields; a visibility switch is not a disclosure control. For an offline handoff, open the exported file without a connection and check the initial view, hover values and any external assets. Keep the units, denominator and key result readable in a static fallback. See Plotly's [trace fields](https://plotly.com/python/reference/scatter/) and [HTML export dependency options](https://plotly.com/python-api-reference/generated/plotly.io.write_html.html).

These are checks on data construction and delivery, not benchmarks of the libraries. For chart selection rather than pipeline validation, see [Figure design](figure-design.md).
